# 人工反馈到下次诊断

## 唯一经验正文

所有离线项目共用 [common-offline-experience.md](common-offline-experience.md)。按主题写明现象、判断方法、适用条件和建议；例子直接附在相关主题下。重复方法合并，已有主题补充，不以链接、分类、候选数量或来源数量代替经验正文。

## 收到人工修正后

1. 保留人工回传原件和实际发出的母版。Word 回传沿用 `--ingest-review <回传.docx> --review-base <实际母版.docx>` 的原件保存与差异提取；导入不冒充用户已确认报告内容。其他历史修正材料直接阅读原件和必要上下文。
2. 仅从经接收来源核验的回传原件相对送审比较母版的实际新增、改写、删除及重点调整中提炼诊断内容和表达方法。对照具体改动片段，不把有改动的整字段都当成新增经验。原样文字只用于理解上下文，不计新增经验或人工认可；回传后生成的同步稿、分册和 Agent 自己的复盘不作为独立回传依据。原件接收、文本变化和具体作者是不同事实，证据不足时明确作者未证实。Agent 的解释、适用条件和证据核验须与回传原文分开，不能冒充人工反馈。去客户化并与唯一正文去重合并，区分观察、原因假设及有条件的行动；不推广单阀等级、数值、固定处方或未经核实的根因。
3. 直接更新同一份经验正文。没有充分依据的阈值不写成标准；有矛盾时收窄适用条件，保留不确定性。原件留在本机项目中备查，不另建经验候选库、逐条批准、状态流转或独立审计表。
4. 下次准备逐阀诊断时自动加载当前全文；无需用户挑选经验版本。已有诊断及冻结结果保持原样。

## 来源归属与学习边界

邮件或上传记录证明外部接收及文件同一性，不证明每句话由人亲写。措辞对照须分开：Agent 编制母版中的既有文字、外部回传新增或改写但具体作者未证实的文字、Agent 收到回传后生成的派生文字，以及本轮 Agent 自己提出的表达建议。字段有改动不代表整字段人工原创，字符串相同也不证明具体作者；若其他版本含相同文字，须核对生成与接收链，不能把回传后的同步稿倒当成回传前来源。没有逐句作者证据时称“回传表达分析”，不称已识别的人工原创风格。经验正文中的表达方法属于 Agent 对表达的归纳，不能冒充用户措辞或人工认可。学习问题的取舍、句子顺序和动作表达，不把错字、笼统断言或未核实的维修处方一并学成标准。

保留回传中的关键区分，例如开向与关向、短时超调与持续振荡、入座过程与粘滑、历史高温与当前报警。只从已核实回传的实际变化提炼新经验；同等级的问题、行动和措辞修改也应分析。原阀的等级、数值和固定维修处方不自动推广。

回传删去异常、改写原因或调整等级，不证明旧观察消失或新损伤成立。回到原始证据核对取舍及适用条件，未核实的方向、数值与根因保留分歧。学习效果以主要问题、风险和主要处理大致匹配为准，检查关键遗漏与无依据新增的故障或维修建议；不要求评级数字、字面措辞、条数和顺序相同。等级差异若伴随相反的实际处置，则比较处置内容，不为凑相同等级改写证据。运行历史与工况、检查对象、备件和复测要求仍按是否影响本阀决定来评价。

回传残句、错字和歧义保留原件备查。仅纠正不改变含义的文字错误；缺少现象、对象、方向或比较词时先查证，不借邻阀句子补成确定事实。工程正文中的示例是 Agent 归纳的条件示意，与来源核验、人工原话及当前诊断区分。

提炼时分别保存三类信息的用途：通用判断方法进入唯一经验正文；有独立来源和时态依据的本阀现场事实进入该阀资料；厂家检查标准保留适用型号、配置和来源。不能把回传诊断结论反写成已确认现场事实，再用于证明新诊断与回传一致。事实补充仍沿用项目资料和参数版本要求。

经验主题可用简短条件对照说明何时观察、补测、检查或处理，兼顾回传删除过度判断和减少无依据维修建议的改动。完整短报告示例必须标为Agent归纳、给出适用前提，不带客户位号、原阀等级和不可迁移的数值；不另建示例库，也不要求逐条采用清单。

工程正文只保留诊断可用的方法、边界与表达示例；上述来源维护说明留在本文件。模型调用、输出结构和完整性要求由现有诊断请求负责，不在经验正文重复说明。

## 实际调用

`prepare-project` 从唯一正文读取全部内容，给每阀保存 `00_experience.md`。`prepare-integrated-diagnosis` 从该输入副本生成请求，全文写入 `experience_text`，正文和本阀完整结构化证据直接放入模型 prompt，提供该阀全部原始文件位置、完整结构化证据、规格、测试执行状态、故障、曲线和技术页。模型在同一次调用中综合判断，经验不作关键词、固定分数、测试标签、top-k 或额外检索筛选。

诊断判断与措辞经验在同一次 `gpt-6.1-sol` / `high` 串行计量调用中使用；不先用旧结论填答案，也不在事后以润色名义改写工程判断。回传原文、旧评级和旧诊断结果不进入本阀诊断请求或读取白名单。历史比较在独立预测保存并封存之后进行；全部目标均须保留成功、失败、未完成及不可比项，不能以先行样本替代已授权的全量验证。

结果只保留当前证据、观察与工程判断、评级、反证、不确定性和建议，不要求采用哪些经验或为什么未采用其他经验。`experience_review`、规则/案例编号和采用记录校验已取消。新运行不生成检索文件，不读取项目经验 JSON。

模型直接阅读 prompt 中的一份完整经验正文和完整结构化证据；请求 JSON 与经验副本留存备查，不再要求重复读取。原始资料及全部图像仍按完整输入要求核对，不以去重为由省略。

全文随原有诊断输入自动冻结。运行中修改共享正文不会改变本次已保存的输入；新准备的诊断使用修改后的正文。输入哈希用于保护已有诊断，不增加用户版本选择或经验审批步骤。上下文实际超限或判断质量出现问题时再处理，禁止静默裁剪全文。

## 验证边界

程序验证检查经验全文（包含末尾）进入逐阀 prompt、当前全部证据和图像覆盖、无经验编号的诊断可正常提交与冻结、全文变更和旧冻结兼容。程序检查通过不等于诊断准确率提高；后续仍以人工回传的实际判断差异来改进正文。

历史回放应先保存并封存独立结果，再打开回传对照；不同试验组逐次只改变提示词或经验正文，保持同阀完整证据、模型和输出合同一致。选取跨场景样本并包括正常或无需维修的情况。已参与经验提炼的历史阀，即使此前未单独调试，也不能称为未见样本或泛化盲测。

提示词变短、经验改成表格或增加示例，都不自动证明报告更简洁或诊断更准确。以实际输出比较内容取舍、遗漏、无依据新增和现场表达；效果未改善时保留候选与结果，恢复试验前输入，不把程序接收通过当作候选有效。来源归属尚未核实的样本单列，不能混入内容匹配率；缩小提示词与否也不能用来判断全文经验注入本身是否有效。
